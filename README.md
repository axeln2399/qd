# qd — Quant Developer, 24 Weeks × 4

My plan to go from senior JVM engineer to hireable **Quant Developer**, studying evenings and weekends.

Everything here uses **relative week numbers**, never calendar dates. Week 1 is whenever I start.

## Files

- **[PLAN.md](PLAN.md)** — the 24-month plan. Phases, milestones, weekly rhythm, checkpoints.
- **[DIAGNOSTIC.md](DIAGNOSTIC.md)** — closed-book math test. **Sit this before Week 1.** It sets the length of the math block.
- **[RESOURCES.md](RESOURCES.md)** — every book, course, paper, dataset and tool, mapped to the phase it's used in.
- **[LOG.md](LOG.md)** — weekly log. Committed every Sunday, no exceptions, including "did nothing" weeks.

## What "ready" means

Three testable exit criteria. All three, not one:

1. **γ — Fluency** (~Week 26): hold a 30-minute conversation about market mechanics without bluffing.
2. **β — Portfolio** (~Week 68): a shipped C++ project a practitioner would respect.
3. **α — Interviews** (~Week 88+): pass a QD technical screen — systems, concurrency, C++, finance-flavoured coding.

## The honest risk

The full C++ pivot is the expensive branch. It costs ~150–200 hours and it means competing partly as a junior in my primary language. **Week 34 is the designated off-ramp** — if C++ still feels like wading through mud then, falling back to JVM-first is an allowed, planned outcome and not a failure.
